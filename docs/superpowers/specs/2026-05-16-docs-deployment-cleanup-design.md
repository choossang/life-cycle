# 문서/배포 정리 설계서

작성일: 2026-05-16
범위: 저장소 루트 문서, GitHub Pages 진입점, 설치 안내 문서 정리
목표: 저장소 첫 화면, 공개 문서 허브, 설치 안내가 서로 충돌하지 않고 하나의 흐름으로 연결되도록 정리한다.

## 1. 목표와 완료 정의

### 목표
- 저장소 방문자가 첫 화면에서 이 저장소의 목적과 주요 산출물을 빠르게 이해할 수 있게 한다.
- GitHub Pages 진입점과 저장소 루트 안내가 서로 다른 역할을 갖도록 분리한다.
- 설치 문서는 저장소 안내와 패키지 설치 안내를 구분해 중복을 줄인다.

### 완료 정의
다음이 모두 충족되면 이 트랙을 완료로 본다.
1. 루트 `index.html`이 저장소 소개 허브 역할을 한다.
2. `docs/index.html`이 공개 문서/배포 허브 역할을 한다.
3. 루트 `INSTALL.md`가 저장소 사용 안내 역할을 한다.
4. `writing/INSTALL.md`는 패키지 설치 전용 문서로 유지된다.
5. 문서 간 링크가 끊기지 않고, 각 문서의 역할이 겹치지 않는다.
6. 공개 노출 문구가 현재 저장소 상태와 모순되지 않는다.

## 2. 현재 상태 요약

### 루트 `index.html`
- 현재 GitHub Pages용 시작 화면 역할을 하고 있다.
- 설계 문서와 Flask 템플릿 HTML 링크가 직접 노출되어 있다.
- 저장소 소개보다는 특정 산출물 나열에 가깝다.

### `docs/index.html`
- 현재는 에세이 단일 링크 중심의 Pages 진입점이다.
- 문서 허브 역할로 쓰기에는 정보량이 적다.

### 루트 `INSTALL.md`
- 현재 source tree에는 존재하지만 worktree에는 아직 반영되지 않았다.
- 역할을 명확히 정하면 저장소 사용 안내 문서로 활용할 수 있다.

### `writing/INSTALL.md`
- 글쓰기 12단계 스킬 패키지 설치 안내 문서로 이미 잘 분리되어 있다.
- 독립 설치 문서로 유지하는 편이 적합하다.

## 3. 정보 구조 설계

역할을 다음처럼 분리한다.

1. 루트 `index.html`
   - 저장소 소개 허브
   - 저장소에 무엇이 들어 있는지 설명
   - 하위 허브/대표 산출물로 안내

2. `docs/index.html`
   - 공개 문서/배포 허브
   - 에세이, 설계 문서, 설치 안내 같은 공개 산출물 링크 모음

3. 루트 `INSTALL.md`
   - 저장소 사용 안내
   - 이 저장소를 어떻게 탐색하고 어떤 하위 문서를 봐야 하는지 설명

4. `writing/INSTALL.md`
   - 글쓰기 스킬 패키지 전용 설치 문서
   - 패키지를 독립적으로 내려받아 사용하는 흐름 안내

## 4. 문서 연결 구조

### 루트 `index.html`
다음 3개 축으로 링크를 정리한다.
- 공개 페이지/문서 보기
- Flask 사주 앱 산출물 보기
- 글쓰기 스킬 패키지 안내 보기

### `docs/index.html`
다음 공개 산출물을 카드형 또는 목록형 링크로 정리한다.
- 에세이 페이지
- 사주 관련 설계 문서
- 글쓰기 스킬 설치 안내

### 루트 `INSTALL.md`
다음 내용을 포함한다.
- 저장소 개요
- 주요 디렉터리 안내
- 공개 문서 위치
- Flask 사주 앱 관련 위치
- 글쓰기 스킬 패키지 위치
- 세부 설치는 `writing/INSTALL.md`를 보도록 링크 제공

### `writing/INSTALL.md`
- 현재 역할 유지
- 상위 허브에서 진입할 수 있도록 링크만 보강
- 루트 `INSTALL.md`와 내용을 복제하지 않는다.

## 5. 수정 원칙

- 한 문서에서 자세히 다루는 내용은 다른 문서에서 반복 설명하지 않는다.
- 루트는 저장소 관점, `docs/`는 공개 관점, `writing/`은 패키지 관점으로 분리한다.
- Flask 템플릿 HTML처럼 직접 실행되지 않는 산출물은 설명 없이 전면 노출하지 않는다.
- 공개 페이지에서 사용자가 혼동할 수 있는 개발자 전용 경로나 내부 작업 파일은 필요한 경우 설명을 붙인다.

## 6. 작업 순서

1. source tree의 `INSTALL.md`, `writing/`를 현재 worktree로 가져온다.
2. 루트 `index.html` 역할을 저장소 소개 허브로 재정리한다.
3. `docs/index.html`을 공개 문서 허브로 확장한다.
4. 루트 `INSTALL.md`를 저장소 사용 안내 문서로 정리한다.
5. 필요 시 `writing/INSTALL.md`의 링크/문구를 최소 보정한다.
6. 링크와 문구의 정합성을 검증한다.

## 7. 검증 전략

다음을 확인한다.
- 루트 `index.html`의 링크가 의도한 대상과 일치하는가
- `docs/index.html`에서 공개 산출물로 이동 가능한가
- 루트 `INSTALL.md`와 `writing/INSTALL.md`의 역할이 겹치지 않는가
- 현재 저장소에 없는 파일을 링크하고 있지는 않은가
- 공개 안내 문구가 현재 상태와 맞는가

## 8. 비범위

이번 트랙에서는 다음을 하지 않는다.
- 글쓰기 스킬 패키지 내부 구조 개편
- Flask 앱 기능 변경
- 새로운 배포 시스템 추가
- 대규모 디자인 리뉴얼

## 9. 결정 기록

1. 문서/배포 정리는 문서 허브 구조로 정리한다.
2. 문서 역할은 루트 허브 / 공개 허브 / 저장소 설치 안내 / 패키지 설치 안내로 분리한다.
3. 첫 번째 남은 트랙은 문서/배포 정리부터 진행한다.
